Graph DSA – Lesson 1: Understanding Graph Types

1. What is a Graph?
A graph is simply a collection of:
- Nodes (vertices): Individual points.
- Edges: Connections between those points.

For example, imagine 4 cities connected by roads.

Image = GVST1



Here:
- A, B, C, D are nodes.
- Lines connecting them are edges.
In Python, we commonly represent a graph using an adjacency list.

graph = {
    0: [1, 2],
    1: [0, 3],
    2: [0],
    3: [1]
}


Meaning:
- City 0 is connected to cities 1 and 2.
- City 1 is connected to cities 0 and 3.
- And so on.


2. The four important graph categories
Before solving a problem, learn to identify these categories.

A. Undirected Graph
====================
The edges have no direction.

If A is connected to B, you can travel from A to B and B to A.

Ex:
graph[0].append(1)
graph[1].append(0)

B. Directed Graph
===================
The edges have directions.

If A → B, you can travel from A to B, but not necessarily from B to A.

graph[0].append(1)


C. Weighted Graph
=================
Each edge has a value (weight).

Example:
- A → B costs 4.
- B → C costs 7.
These weights might represent distance, time, or cost.


D. Unweighted Graph
====================
Edges have no associated weights.

We only care whether two nodes are connected.

Important: These are not mutually exclusive categories. For example, a graph can be both directed and weighted.


3. Tree vs General Graph
=========================
This is particularly important for LeetCode.

A Tree is a special type of graph.

A tree has two important properties:
1. It is connected.
2. It has no cycles.
For an undirected tree:

E = V-1


n = 5
edges = [
    [0, 1],
    [0, 2],
    [1, 3],
    [1, 4]
]

Here:
- Nodes = 5
- Edges = 4
- All nodes are connected.
- No cycles exist.

Therefore, this is a Tree.



4. How to identify a Tree in a LeetCode question?
Whenever you see a graph problem, check these three things.
Check	What to look for
1. Connected?	Can every node reach every other node?
2. Cycles?	Is there any circular path?
3. Edge count?	For an undirected tree, E = V - 1



If all three conditions are satisfied, it is a Tree.

Important: The edge-count formula alone is not sufficient. We also need connectivity (or no cycles).


Ex:1
=====
n = 5
edges = [[0,1], [0,2], [1,3], [1,4]]


- 5 nodes
- 4 edges
- Connected
- No cycles
Result: Tree.


Ex:2
=====
n = 3
edges = [[0,1], [1,2], [2,0]]

- 3 nodes
- 3 edges
- Connected
- Has a cycle: 0 → 1 → 2 → 0
Result: General Graph, not a Tree.


Ex:3
=====
Disconnected graph

n = 5
edges = [[0,1], [1,2], [3,4]]

- 5 nodes
- 3 edges
- No cycles
- Not all nodes are connected.
Result: General Graph, not a Tree.


5. How does this help us choose DFS or BFS?
Here's an important point:

DFS and BFS work on both Trees and General Graphs.

The difference is how we handle revisiting nodes.



Situation	                                    DFS/BFS approach
Tree	                                        DFS or BFS; parent tracking can prevent going backwards
General graph with cycles	                    DFS or BFS with visited
Find shortest path in an unweighted graph	    BFS
Explore deeply along a path	                    DFS



For example, in LeetCode 1466, 
we used a visited set because we created an undirected 
adjacency list from directed roads.

This prevented DFS from travelling back to an already visited city.
